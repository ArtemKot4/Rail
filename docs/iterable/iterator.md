## Итераторы

Итератор - механизм, благодаря которому работают переборы коллекций в циклах. 

Язык Rail позволяет создавать свои итераторы и использовать их в переборах.

## Синтаксис

Для создания итератора мы используем ключевое слово `iterator` вместо `function*` из JavaScript.

```rail
iterator название(аргументы): возвращаемый_тип_данных { 
    //тело итератора
}
```

## Аналог return - yield

Итераторы похожи на функции, однако механизм возврата значения другой.

`yield` - ключевое слово, которое позволяет возвращать значение из итератора. Сколько раз в итераторе оно было вызвано, столько раз он выдает значение. Таким образом массивы выдают значения столько раз, сколько у них длина (length).

```rail
iterator название<T>(аргументы): возвращаемый_тип_данных { 
    yield значение;
}

//но <T> необязателен
```

## Пишем свой итератор

Напишем итератор, который будет представлять из себя обратный отсчёт.

```rail
iterator countdown<T extends int[]>(start: int): T {
    while(start >= 0) {
        yield start;
        start--;
    }
}
```

### Используем в for

```rail
for(let n of countdown(3)) {
    console.log(n);
}
// 3
// 2
// 1
// 0
```

### Используем в while

Для использования в while итератор имеет метод `hasNext`, возвращающий `true`, если ещё остались сохранённые через `yield` значения, которые не были получены.

Так же есть функция `next`, которая совершает итерацию: переход к следующему элементу, которое удержит `yield`.

```rail
let cd = countdown(3);
while(cd.hasNext()) {
    console.log(cd.next());
}
// 3
// 2
// 1
// 0
```

### Используем как генератор коллекций
Если коллекция реализует оператор +, она автоматически может использоваться в итераторе для её генерации, если это позволено дженериком `<T>`.

В нашем итераторе есть ограничение, поэтому он может генерировать коллекцию только в виде массива чисел `int`.

```rail
const cd = countdown(3)<int[]>(); //[3, 2, 1, 0]
```

## Разбираемся, как работает range

Мы немножко потренировались писать свои итераторы, а теперь попробуем разобраться, как работает один из встроенных.

Выглядит он примерно так:

```rail
iterator range(start: int, end: int, step: int): int {
    while(start < end) {
        yield start;
        start += step;
    }
}
```

### Используем в for

```rail
for(let n of range(0, 3, 1)) {
    console.log(n);
}
// 0
// 1
// 2
```

## Анонимные итераторы

Анонимные итераторы - довольно интересный способ записи. Он не принимает в себя аргументы, а является некоторой записью о том, как проитерировать помещённую коллекцию.

Если нужно получить результат, нужно вызвать его как функцию при помощи круглых скобок, указать в какую коллекцию нужно его поместить можно через принимаемый дженерик.

Анонимный итератор выглядит как цикл в одну строку кода, но с префикс-результатом, который вернётся после каждой итерации.

Выглядит это примерно так: `возвращаемое_значение цикл`, где цикл, чаще всего применяется for.

### Разбираемся с записью

Разберём на нескольких примерах:

1. Анонимный итератор с заготовленным значением.
   
   ```rail
   const collection = [1, 2, 3, 4, 5]
   const _for = value * 2 for(const value of collection);
   ```

2. Анонимный итератор с принимаемыми аргументами.
   Это не особенность синтаксиса, а один из вариантов использования лямбд, в данном случае для возврата итератора, который использует аргументы. Работа с такими лямбдами такая же, как с замыканиями. Таким образом мы можем создавать итераторы с значениями, которые не заготовлены заранее, как это было в случае помещения в переменную в коде.
   
   ```rail
   const _range = (from: number, to: number, step: number = 0) => value for(let value = from; value < to; value += step);
   
   
   ```
Мы создали два итератора, `_for` и `_range`, но сами по себе итераторы не имеют смысла, если мы их не вызываем. Так давайте это исправим!

### Вызываем итераторы

Для начала разберёмся с синтаксисом вызова, выглядит он так: `итератор<коллекция, в которую положить значения>()`. По сути это ничем не отличается от вызова функции с дженериком.

В случае использования итератора сразу внутри коллекции, дженерик-тип можно не указывать, в таком случае он сможет перенять тип данных самой коллекции.

Выводить итераторы мы будем двумя способами: 

1. Вызывать внутри коллекции, что является **списковым включением**.

2. Получать коллекцию из итератора при помощи вызова с дженерик-типом.

Перейдём к вызовам:

1.  Выводим `_for` 
    ```rail
    console.log(_for<int[]>()); //[2, 4, 6, 8, 10], создали коллекцию при помощи вызова итератора
    const collection_injected = [_for()]; //получили значения после выполнения итератора внутрь массива
    print(collection_injected); //[2, 4, 6, 8, 10]
    ```

2. Выводим `_range`.

   Поскольку `_range` не итератор, а лямбда, первым вызовом скобок мы получаем итератор, что является результатом вызова `_range`, а после вызываем сам итератор.
   
   ```rail
   console.log(_range(1, 5)<int[]>()); //[1, 2, 3, 4]
   console.log([_range(1, 5)()]); //[1, 2, 3, 4]
   
   //так же можно упростить, положив итератор в отдельную переменную
   const iter = _range(1, 5);
   console.log(iter<int[]>()); //[1, 2, 3, 4]
   ```

## Типизация итераторов
Представим, что нам нужно принимать массив итераторов, но как мы узнаем, какие итераторы ложить?

Всё просто! Можно сами итераторы и использовать как принимаемый тип данных. Мы писали итератор `range` в самом начале, на его примере и посмотрим:

```rail
const array: range[] = [range(1, 10), range(10, 20)];
```

Если захотим выполнить, можем сделать это при помощи анонимного итератора:

```rail
const arrayCompleted = array.map(iteratorValue => value for (const value of iteratorValue) ());
```

Или ещё проще, но тогда придётся следовать ограничению `T`, если оно есть у используемого итератора:

```rail
const arrayCompleted = array.map(iteratorValue => iteratorValue<int[]>());
```

Итераторы можно принимать где угодно, вот пример с функцией:

```rail
function buildRange<T>(iteratorArg: range): T[] {
    return iteratorArg<T[]>();
}
```
