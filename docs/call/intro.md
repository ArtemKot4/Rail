## Кратко и о главном
### Функции
[Функции](function.md) - это именованные блоки кода, подписанные собственным названием, которые можно вызывать неограниченное количество раз, передавая в аргументы значения, если того требует перегрузка.

Функции созданы для того, чтобы всегда возвращать значение.

### Процедуры
[Процедуры](procedure.md) - тоже именованные блоки кода, но они не возвращают значения, а только выполняют какие-то действия.

### Лямбда-функции
[Лямбды](lambda.md) - анонимные функции, которые можно вызывать неограниченное количество раз, передавая в аргументы значения, если того требует перегрузка.

Лямбды зачастую нужны для передачи их в функции или процедуры и редко используются как самостоятельные единицы.

## Тело
### Тело функции
Это код внутри `{}`, который и будет выполняться при вызове.

Имеет свою область видимости: переменные, созданные внутри функции, не доступны вне её кода.

Можно переопределять значения из внешних областей видимости

```rail
let word = "hello";

procedure change() {
    word = "world";
}

console.log(word); //hello
change();
console.log(word); //world
```

Функции предполагают в себе return при завершении для возврата значения возвращаемого типа:
```rail
function get(): string {
    return word;
}

console.log(get()); //world
```

`return` завершает выполнение функции и возвращает значение. Иногда используется для раннего выхода если это требуется:

```rail
const validInt: int = 15;

function hasValidInt(arr: int[]): int? {
    for(let num of arr) {
        if(num == validInt) return num;
    }
    return null;
}
```

### Выводимый тип возвращает значение
Это способ создавать функции-предикаты (возвращающие логическое `да` или `нет`, `true` или `false`) с возвращаемым типом с условием.

Синтаксис следующий:
`ключевое_слово название(аргументы): условие;`

Рассмотрим на примере проверки корректного возраста для различных операций:
```rail
// В других языках
function isValidAge(age: number): boolean {
    return age >= 18;
}

// В Rail
function isValidAge(age: int): age >= 18;
```

Однако в случае тернарного оператора можно добиться и более сложного результата.
Сделаем функцию, чтобы получить ответ в виде строки:
```rail
function isValidAge(age: int): age >= 18 ? "да" : "нет";
```
В таком случае перечисление возвращаемых типов будет вычисляться исходя из того, что может вернуть та или иная часть операции, на этапе компиляции.

### (отменено) Работа с исключениями
Бывают случаи, в которых функция использует внутри себя вызовы, которые могут выбросить исключения. Это не очень хорошо, если не учитывается явно, ведь такие вызовы могут положить работу всей программы или ключевых её частей. К счастью компилятор заботится о безопасности и не даст скомпилировать небезопасные части.

Напишем простую функцию:
```rail
function readFile(filePath: string) {
    //...чтение, return file
    //если не получилось:
    throw RuntimeError("No such file of directory");
}
```
И получим ошибку!

В чём дело? Rail относится к исключениям очень аккуратно, и если они вызываются, они должны быть либо обработаны, либо ожидаемы. Это позволяет программам всегда знать, что ожидать от того или иного инструмента и правильно реагировать.

Поскольку случай вызова предполагает исключение, если файл не найден, мы усовершенствуем нашу функцию при помощи фишки, которая пришла из Java.

#### Изучаем `throws`
`throws` - это именно тот оператор, который говорит компилятору, что здесь ожидается возможный выброс исключения при вызове. Пишется после аргументов после возвращаемого типа данных, если он требуется.

Перепишем нашу функцию:
```rail
function readFile(filePath: string): File, throws RuntimeException {
    //...чтение, return file
    //если не получилось:
    throw RuntimeError("No such file of directory");
}
```
Вот и всё, теперь компилятор знает, что эта процедура предусматривает выброс исключения и будет это учитывать при использовании.

Все функции и процедуры, помеченные при помощи `throws`, точно так же должны обрабатываться через try catch, как и обычные ошибки при вызове. Иначе то тело функции или процедуры, в котором вложен вызов другой функции или процедуры, должно унаследовать throws предыдущего явно для указания возможного исключения:

```rail
function readFile(filePath: string): File, throws RuntimeException {
    //...чтение, return file;
    //если не получилось:
    throw RuntimeError("No such file of directory");
}

//...представим условный FileReader(path: string): string[]; где string[] это пути к файлам
//...и условный File

//первый вариант
function readFiles(path: string): File[] {
    const fileReader = FileReader(path);
    const files: File[] = [];

    for(const filePath of fileReader) {
        try {
            files += readFile(filePath);
        } catch {
            console.log("Файл по директории "filePath" не записан");
        }
    }
    return files;
}

//второй вариант
function readFiles(path: string): File[], throws RuntimeException {
    const fileReader = FileReader(path);
    const files: File[] = [];

    for(const filePath of fileReader) {
        files += readFile(filePath);
    }
    return files;
}
```
**Важно!** Запятая перед `throws` нужна только в том случае, если есть возвращаемый тип. Например в процедурах `throws` будет писаться сразу после аргументов.

```rail
function foo(): int, throws Error  //с запятой
procedure bar() throws Error       //без запятой
```
## Механизм отложенного вызова: `defer`
Этот механизм был вдохновлён языком Go, и очень удобен для использования в операциях, которые работают с освобождаемыми ресурсами.

Давайте рассмотрим простой пример без defer.
```rail
function getTextFromFile(fileName: string): string, throws RuntimeException {
    //нам нужно гарантировать, что файл закроется даже если функция выбросит исключение
    try {
        const openedFile = //...открыли_файл_через_какой-то_способ(fileName);
    
        const text: string = openedFile.getText();
        openedFile.close(); //закрываем файл перед завершением работы
        return text;
    } catch(error) {
        openedFile.close(); //закрываем файл при выброшенном исключении тоже
        throw error; //не мешаем исключению быть выброшенным после завершения
    }
}
```
В данном случае у нас закрывается файл и при исключении, и перед возвратом текста. Это всё, конечно, работает отлично, но можно сделать то же самое намного короче благодяра новому механизму:
```rail
function getTextFromFile(fileName: string): string, throws RuntimeException {
    const openedFile = //...открыли_файл_через_какой-то_способ(fileName);
    defer openedFile.close();

    const text: string = openedFile.getText();
    return text;
}
```
И теперь компилятор преобразует код в первый вариант самостоятельно, и будет выглядеть он почти так же:

```rail
function getTextFromFile(fileName: string): string, throws RuntimeException {
    const openedFile = //...открыли_файл_через_какой-то_способ(fileName);
    const __callDefer = () => {
        openedFile.close();
    }
    try {
        const text: string = openedFile.getText();
        __callDefer();
        return text;
    } catch(error) {
        __callDefer();
        throw error;
    }
}
```
Откуда взялся `__callDefer`? Дело в том, что defer в функции может быть неограниченное количество, и все вызовы внутри будут помещены в `__callDefer` в обратном порядке вызова. Это системная функция, вставляемая компилятором для сокращения кода большого количества отложенных выполнений, работающая на любом бекенде.

**Важно!** Если ваша функция или процедура не способна выбросить исключение: не использует `throws`, конструкция `try-catch` не будет добавлена.

**Тоже важно!** defer регистрируется только после успешного выполнения кода до него. Если исключение произошло до регистрации defer, отложенный вызов не произойдёт.

### Синтаксис defer
Есть несколько способов использовать `defer`, в зависимости от того, один вызов нужно отложить или какое-то количество операций.
1.  ```rail
    procedure logDefer() {
        defer console.log("world");
        defer console.log("hello");

        console.log("Тексты defer'ов: ")
    }

    logDefer();
    //Тексты defer'ов:
    //hello
    //world
    ```

2.  ```rail
    procedure logDefer() {
        defer {
            console.log("world");
            console.log("hello");
        }
        console.log("Текст defer'а: ")
    }

    logDefer();
    //Текст defer'а:
    //hello
    //world
    ```
Как мы видим, defer'ы вызываются в обратном порядке, снизу вверх. Причём вызываются действительно в самом конце работы функции.

## Вызов
Создадим функцию для примеров:
```rail
function multiply(...args: int[]): int {
    let result = 1;
    for(let arg of args) {
        result *= arg;
    }
    return result;
}
```

Для вызова нам нужно написать название и передать аргументы.

```rail
название(аргументы);
multiply(1, 2, 3);
```

Если вам нужно передать значения из массива или кортежа фиксированного размера (если аргумент не является rest), вы можете воспользоваться spread оператором

```rail
let arr = [1, 2, 3];
console.log(multiply(...arr)); // 6
```

Есть ещё один способ вызова, иногда он более удобный, но нужно аккуратно использовать, чтобы код оставался читаемым:
```rail
console.log "hello rail!";
```
При таком вызове функций в аргументы будет собрано всё до точки с запятой. Это работает лишь в некоторых контекстах и не всегда желательно.

## Рекурсия
Рекурсия - вызов функции внутри самой себя.

```rail
// Важно: глубокая рекурсия может вызвать переполнение стека
function factorial(n: int): int {
    if(n == 0) return 1;
    return n * factorial(n - 1);
}
```

## Замыкание
Замыкание - функция, которая сохраняет значения переменных, которые были вычислены во время выполнения функции и возвращает функцию.

```rail
function counter() {
    let count = 0;
    return function() {
        count++;
        return count;
    }
}

let count = counter();
console.log(count()); // 1
console.log(count()); // 2
console.log(count()); // 3
```
