# Условные типы
Поскольку Rail очень сильно связан с системой типов, он позволяет программировать их поведение. Это удобно - позволяет на основе входящих типов данных принимать программе решения о том, какие данные будут приняты, при этом без написания проверок if-else вручную.

## Операторы
Дальше будет представлена таблица операторов, поддерживаемых в выражениях условных типов.

| Оператор | Описание | Пример | Результат |
| --- | --- | --- | --- |
| `T extends U` | Проверяет, является ли тип `T` подтипом типа `U`. | `T extends int` | `true`, если `T` является типом `int`, иначе `false`. |
| `T super U` | Проверяет, является ли тип `T` предком типа `U`: был ли унаследован `T` от `U` в иерархии. При этом наследники `T` не будут приняты | `T super MyClass` | `true`, если `T` является классом `MyClass` или его наследником, иначе `false`. |
| `T satisfies { object: unknown }` | Проверяет, удовлетворяет ли структура  типа `T` структуре объекта или литерального типа. | `T satisfies { object: unknown }` | `true`, если `T` по структуре содержит свойство `object` с указанным типом данных, иначе `false`. |
| `T is U` | Проверяет, является ли `T` строго типом `U` | `<T is int>` | `T` может быть <u>только</u> `int` |
| `condition1 && condition2` | Проверяет, являются ли оба условия истинными. | `T extends Type1 && U extends Type2` | `true`, если оба условия истинны, иначе `false`. |
| `condition1 \|\| condition2` | Проверяет, является ли хотя бы одно условие истинным. | `T extends Type1 \|\| U extends Type1` | `true`, если хотя бы одно условие истинно, иначе `false`. |
| Тернарный оператор `? :` | Возвращает первое выражение, если условие истинно, иначе второе. | `T extends U ? true : false` | `true`, если `T` является типом `U`, иначе `false`. |
| `const` | Мы ставим ограничение, чтобы значение не могло быть изменено | `<T, U = T extends int ? const T : T>` | Если тип `T` является типом `int`, то `U` будет типом `const int`, а значит значение, которым будет тип `U`, не сможет быть изменено - если `T` не `int`, `U` будет типом `T`.
| Ограничение по ссылке: `&` | Заставляет передавать аргументы по ссылке, если аргументы дженерика предполагают это ограничение | `T extends float \| int&` | Если `T` это `int`, значение будет передано по ссылке, если `float`, то скопировано. |
| `!` | Меняет условия для `extends`, `super`, `satisfies` и `is` | `T !extends number` | Теперь `T` <u> не может быть `number` </u> |
| `static` | Данный оператор позволяет делать то, что делает `typeof static`: извлекать литеральные типы данных. | `<T extends static int>` | Переданное число останется им, а не станет `int`. | 

### Пишем дженерик, который меняет значения переменных только для `int` чисел
```rail
function changeValue<T extends int& | float>(value: T): T {
    value++;
}

let intNumber = 1;
let floatNumber = 1.0;

changeValue(intNumber);
changeValue(floatNumber);

console.log(intNumber); //2
console.log(floatNumber); //1.0
```
Почему `floatNumber` не поменялся? Дело в том, что согласно ограничению дженерика, он передаёт по ссылке только int числа, остальные просто копируют свои значения, а потому эти значения могут быть изменены только внутри функции, но на внешние не влияют.
